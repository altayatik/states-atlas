# Altay & Aidi's Travel Atlas

A personal travel atlas built with React, Vite, MapLibre, Firebase Hosting, Firestore, and Firebase Auth. The app includes the state-level road atlas and the National Parks rankings page.

- Source folder: `/Users/altayatik/Desktop/atlas/states-atlas`
- Source repo: `https://github.com/altayatik/states-atlas`
- Public deployment repo: `https://github.com/altayatik/atlas`
- Public URL: `https://altayatik.com/atlas/`
- Editor URL: `https://altayatik.com/atlas/#/edit`

The public app is read-only. Editing uses Google sign-in and Firestore Security Rules, so the app works on the Firebase Spark/free plan with no Cloud Functions and no Blaze upgrade.

## Local Dev

```bash
npm install
npm run dev
```

The Vite base path is `/atlas/`.

## Frontend Environment

Copy `.env.example` to `.env.local` and fill in the Firebase Web app config:

```bash
VITE_FIREBASE_API_KEY=
VITE_FIREBASE_AUTH_DOMAIN=
VITE_FIREBASE_PROJECT_ID=
VITE_FIREBASE_STORAGE_BUCKET=
VITE_FIREBASE_MESSAGING_SENDER_ID=
VITE_FIREBASE_APP_ID=
VITE_FIREBASE_MEASUREMENT_ID=
```

Firebase Web config is public client configuration, but `.env.local` is ignored so local machine settings do not churn in Git.

## Firebase Setup

Enable these Firebase products:

- Firestore Database in Native mode
- Firebase Hosting
- Authentication with the Google provider

No Cloud Functions are required.

In Firebase Console > Authentication > Sign-in method:

- Enable Google
- Make sure authorized domains include `altayatik.com`
- Keep Firebase's default hosting domain authorized as needed

## Firestore Collections

### `stateTravelEntries`

Document ID is the state/province code, such as `CA`, `AK`, or `CAN`.

Fields:

- `state_code`
- `state_name`
- `status`
- `first_visited_year`
- `favorite_memory`
- `badges`
- `vibe_rating`
- `honorable_mention`
- `cities_visited`
- `parks_visited`
- `created_at`
- `updated_at`

### `parkRankings`

Document ID is generated by Firestore or imported from the old Supabase `id`.

Fields:

- `park_name`
- `park_code`
- `is_custom`
- `scenery`
- `visitor_center`
- `facilities`
- `trails`
- `roads`
- `notes`
- `visited_date`
- `honorable_mention`
- `created_at`
- `updated_at`

## Security Rules

Rules live in `firestore.rules`.

- Public reads are allowed for `stateTravelEntries` and `parkRankings`.
- Creates, updates, and deletes are allowed only for verified Google admin accounts: `altayatik01@gmail.com` and `aidima821@gmail.com`.
- All other reads/writes are denied.

Deploy rules and hosting:

```bash
npx firebase-tools deploy --only firestore,hosting --project states-atlas
```

## Editing

Open:

```text
https://altayatik.com/atlas/#/edit
```

Sign in with Google. Only `altayatik01@gmail.com` and `aidima821@gmail.com` can write because Firestore rules enforce those emails. Other accounts can sign in but cannot access the editor or write data.

## Supabase Backup

Supabase exports were saved locally in:

```text
migration-backups/state_travel_entries.supabase-export.json
migration-backups/park_rankings.supabase-export.json
```

The folder is ignored and should not be committed.

## Troubleshooting

If Google sign-in fails, confirm the Google provider is enabled in Firebase Auth and `altayatik.com` is an authorized domain.

If saving fails with `This account is not allowed to edit this atlas.`, confirm you are signed in as `altayatik01@gmail.com` or `aidima821@gmail.com` and that the deployed `firestore.rules` file contains that email.
